    README¶

    @nospt/backstage-plugin-apigee-backend

    The backend package of the Backstage Apigee plugin. It discovers your Apigee X proxies, sharedflows, and Apigee API Hub definitions, registers them as Backstage catalog entities — enriched with ownership, lifecycle, specs, tags, and source-repository links — and stitches your existing backend components to the API proxies they expose.

    Built on the Backstage New Backend System.

    What this package provides

    Two backend features are exported:

    Export Type Purpose
    catalogModuleApigee (named export) Catalog backend module The core integration: a scheduled entity provider that syncs Apigee + API Hub into the catalog, plus the repository-stitching processor.
    default export Standalone backend plugin A minimal plugin mounted at /api/apigee exposing /health and /hello (handy as a liveness probe).

    Architecture

    flowchart LR
  MGMT["Apigee Management API"]

  CAT[("Backstage catalog")]

  HUB --> HC

    On a schedule (default: hourly) the entity provider reads from Google Cloud, the entity builder transforms the raw data into Backstage entities, and the provider emits them to the catalog as a single full mutation.

    Data sources
    Client Google Cloud API Reads
    ApigeeClient Apigee Management API v1 API proxies, deployments, and revisions (base paths).
    ApiHubClient Apigee API Hub REST v1 API definitions, versions, specs, and metadata.
    SharedflowClient Apigee Management API v1 Sharedflows.

    All calls are GET-only.

    Installation

    Add the package to your backend:

    yarn --cwd packages/backend add @nospt/backstage-plugin-apigee-backend

    Register the features in packages/backend/src/index.ts:

    import { catalogModuleApigee } from '@nospt/backstage-plugin-apigee-backend';

// Optional standalone /api/apigee health router (default export)
backend.add(import('@nospt/backstage-plugin-apigee-backend'));
// Apigee → catalog discovery + repository stitching (named export)
backend.add(catalogModuleApigee);

    The catalog module is a named export, so import it by name — backend.add(import(...)) alone would only register the default (health-router) export.

    Authentication & IAM

    The clients authenticate with Google Cloud Application Default Credentials (ADC) using the https://www.googleapis.com/auth/cloud-platform scope.

    • Local development — run gcloud auth application-default login, or set GOOGLE_APPLICATION_CREDENTIALS to a service-account key file.
    • Deployed — attach a service account (for example via Workload Identity on GKE) with read-only access to Apigee and API Hub. Read-only roles are sufficient and recommended, for example:
    • roles/apigee.readOnlyAdmin — read proxies, deployments, and sharedflows.
    • an Apigee API Hub viewer role such as roles/apihub.viewer — read API Hub definitions and specs.

    The module never writes to Apigee or API Hub.

    Configuration

    Everything lives under the apigee key. Apigee backend functionality is enabled by default, and apigee.orgs is required when enabled — the module fails fast at startup if it is missing or empty.

    To keep both registered backend features idle without organizations, Google credentials, or Apigee API calls, disable Apigee:

    apigee:
  enabled: false

    The setting is read at startup; restart the Backstage backend after changing it. The local backend dev harness honors the same flag, skipping its sync provider and stitching demo when disabled.

    apigee:
  enabled: true # optional; defaults to true
  # --- required ---
  orgs:
    - name: apigee-x-private-p-495866 # Apigee org name
      projectId: apigee-x-private-p-495866 # GCP project that owns the org
      githubOrgSlug: my-github-org # optional: source-repo link fallback
      environments: [prod-1, dev-1] # optional: restrict synced environments
      apiHubMappings: # optional: proxy -> API Hub apiId overrides
        my-proxy: my-api-hub-id

  # --- optional ---
  apiHubLocation: global # API Hub region (default 'global')
  defaultOwner: group:default/platform # owner when API Hub supplies none
  defaultTags: [apigee] # tags on every entity (default ['apigee'])
  system: system:default/apigee-x # System every entity is grouped under
  specMaxBytes: 512000 # inline-spec size cap in bytes (default 500 KB)
  syncIntervalMinutes: 60 # sync cadence (default 60)
  debugAttributes: false # log raw payloads (troubleshooting aid)
  environmentLifecycle: # map Apigee env -> Backstage lifecycle
    prod-1: production
    dev-1: experimental
  schedule: # full schedule; overrides syncIntervalMinutes
    frequency: { minutes: 60 }
    timeout: { minutes: 10 }
    initialDelay: { seconds: 30 }
    Key Type Default Description
    apigee.enabled boolean true Set to false to keep the backend plugin and catalog module registered but idle until restart.
    apigee.orgs array — (required) Apigee organisations to sync. Each entry needs name and projectId.
    apigee.orgs[].environments string[] all Restrict which environments are considered for deployment and lifecycle.
    apigee.orgs[].githubOrgSlug string — Derives a source-repo link when API Hub supplies none.
    apigee.orgs[].apiHubMappings map — Override the API Hub apiId for proxies whose slug differs.
    apigee.apiHubLocation string global API Hub region (e.g. europe-west1).
    apigee.defaultOwner string group:default/unknown Fallback spec.owner (must be an entity ref).
    apigee.defaultTags string[] ['apigee'] Tags applied to every synced entity.
    apigee.system string system:default/unknown spec.system grouping ref; the module also emits this System entity.
    apigee.specMaxBytes number 512000 Specs larger than this are linked (cloud.google.com/spec-url) instead of embedded.
    apigee.syncIntervalMinutes number 60 Sync cadence. Ignored when apigee.schedule is set.
    apigee.schedule object — Full task schedule (frequency / timeout / initialDelay); overrides syncIntervalMinutes.
    apigee.environmentLifecycle map — Maps Apigee env names to production / experimental / deprecated.
    apigee.debugAttributes boolean false Logs raw Apigee/API Hub payloads before transformation (needs backend.logger.level: debug).
    apigee.useMockData boolean false Skips GCP entirely and serves bundled sample proxies, APIs, specs and sharedflows for every configured org. For local development without Apigee access.

    Entity mapping

    Source (Apigee / API Hub) Backstage entity spec.type spec.lifecycle Notes
    API proxy (runtime) Component api-proxy from deployments Emits providesApis: [<proxy>], linking it to its own API.
    API proxy (contract) API API Hub type, default openapi from deployments Enriched with API Hub metadata and spec when matched.
    Sharedflow Component (namespace apigee-sharedflows) library production —
    API Hub API with no matching proxy API API Hub type, default other experimental Carries cloud.google.com/api-hub-id.
    Grouping system System — — Named from apigee.system.

    Because a proxy Component and its API share the same name and namespace, Backstage automatically creates the providesApi / apiProvidedBy relations — surfacing the Provided APIs and Providers cards with no custom UI.

    Field & metadata resolution
    Field Source (in precedence order)
    spec.owner API Hub Team attribute → API Hub owner.displayName → apigee.defaultOwner → group:default/unknown.
    metadata.labels.department API Hub Business unit attribute (slugified, capped at 63 chars). Exposed as the Department facet in the UI.
    metadata.tags apigee.defaultTags (default ['apigee']) first, then API Hub categories and the API Style attribute (e.g. rest), slugified and deduplicated.
    Source repository link API Hub Documentation URI → first http(s) sourceMetadata value → githubOrgSlug/<entity> convention. Only http(s) URLs are ever emitted.
    spec.definition Embedded spec when within apigee.specMaxBytes; otherwise linked via cloud.google.com/spec-url. A non-empty placeholder is used when no spec exists.
    Version cloud.google.com/version, taken from the spec's info.version.
    spec.lifecycle Highest-ranked lifecycle across deployed environments via environmentLifecycle (production > experimental > deprecated); when unset, any ready deployment maps to production.
    Annotations reference
    Annotation Applied to Meaning
    cloud.google.com/orgs proxy Component & API Comma-joined org names the proxy exists in.
    cloud.google.com/org hub-only API Org the definition was discovered under.
    cloud.google.com/proxy-name proxy Component & API Raw Apigee proxy name (before slugifying).
    cloud.google.com/base-path proxy Component Comma-joined proxy base paths.
    cloud.google.com/has-spec Component & API 'true' / 'false' — whether a real spec is available.
    cloud.google.com/spec-url API Link to the spec when it is too large to embed.
    cloud.google.com/version proxy Component & API Spec info.version.
    cloud.google.com/category API Comma-joined API Hub categories.
    cloud.google.com/api-hub-id hub-only API Full API Hub resource name.
    cloud.google.com/<org>.lifecycle proxy Component Per-org resolved lifecycle.
    cloud.google.com/<org>.env.<env>.revision proxy Component Deployed revision per environment.

    Backstage annotation keys allow a single / (the prefix), so per-org/environment data is encoded in the dot-separated suffix.

    Repository Stitching

    A Backstage CatalogProcessor (ApigeeStitchingProcessor) links a backend Component to its proxy API entity by emitting the native providesApi / apiProvidedBy relations. This surfaces the standard "Provided APIs" card on the component page and the "Providers" card on the API page — with zero custom UI. A repository opts in by adding nos.pt/apigee-* annotations to its catalog-info.yaml.

    Annotation styles

    Direct mapping (active in this release):

    apiVersion: backstage.io/v1alpha1
kind: Component
metadata:
  name: orders-service
  annotations:
    nos.pt/apigee-api-name: my-proxy
    nos.pt/apigee-project-id: apigee-x-public-p-123
spec:
  type: service
  owner: team-orders
  lifecycle: production

    TargetServer-based mapping (documented; resolution planned, not yet active):

    metadata:
  annotations:
    nos.pt/apigee-targetserver-hostname: backend.nos.pt
    nos.pt/apigee-targetserver-port: '443'
    Precedence rule

    When both styles are present, the TargetServer-based mapping is the preferred resolution path (STITCH-02). The direct API-name mapping is the fallback, used when no TargetServer annotation is present or when TargetServer resolution is ambiguous (for example, a generic load balancer shared by many proxies).

    In this release only the direct-mapping path is implemented. TargetServer resolution is planned but not yet active — no TargetServer data is captured by the entity provider yet (see 04-CONTEXT D-01). The processor is structured around a resolution-strategy seam so the TargetServer branch slots in without rework.

    Apigee → Backstage mapping
    Apigee concept Backstage entity
    API proxy (implementation) kind: Component, spec.type: api-proxy
    API proxy (contract) kind: API, spec.type from API Hub (default openapi)
    Sharedflow kind: Component, spec.type: library
    Proxy Component ↔ its own proxy API spec.providesApis: [<api-name>] (emitted by the entity provider)
    Backend repo component ↔ proxy API providesApi / apiProvidedBy relation
    Resolution detail

    The target API entity ref is deterministic: api:default/<slugify(nos.pt/apigee-api-name)>. The processor reads the annotations, synthesizes the ref, and emits the relation pair — no live catalog lookup is needed. A partial annotation set (e.g. nos.pt/apigee-api-name without nos.pt/apigee-project-id) or an empty/unresolvable value is skipped with a warning (warn-and-skip), so no malformed relations are emitted.

    Example fixture

    See examples/components.yaml for ready-to-register sample Component entities exercising both annotation styles — useful for local smoke testing of the stitching processor.

    API Hub enrichment

    kind: API entities discovered from Apigee are enriched with API Hub metadata (owner, description, categories, department, spec). The "Source repository" link on the API entity page (metadata.links) is resolved in this order:

    1. API Hub Documentation field (Api.documentation.externalUri) — NOS records the proxy's GitHub repository URL here (e.g. https://github.com/nosportugal/apigee-x-proxy-<proxy-name>).
    2. The first sourceMetadata[] entry whose value is an http(s) URL (repo/git/source types preferred when several qualify).
    3. The apigee.orgs[].githubOrgSlug convention: https://github.com/<slug>/<entity-name>.

    Only http(s) URLs are ever emitted; javascript:/data: values are rejected to prevent link injection into rendered entity pages.

    Apigee API Hub link

    Each kind: API entity that resolves to an API Hub definition also carries an "Apigee API Hub" link (metadata.links) that deep-links to the API's overview page in the Google Cloud console. The URL is derived from the API Hub resource name (projects/<project>/locations/<location>/apis/<apiId>):

    https://console.cloud.google.com/apigee/api-hub/locations/<location>/apis/<apiId>/overview?project=<project>

    Proxies with no API Hub match carry no such link.

    Department label

    Both the proxy kind: Component and its kind: API entity carry a department label (metadata.labels.department) sourced from the Apigee API Hub Business unit attribute. Business unit is a top-level API Hub AttributeValues field; a user-modelled business-unit attribute is scanned only as a fallback. The raw value is slugified and capped at 63 characters so it is always a valid Backstage label value. The frontend catalog page exposes it as a Department filter facet.

    Default tags

    Every synced entity carries default metadata.tags, configurable via optional apigee.defaultTags and defaulting to ["apigee"] when unset or empty:

    apigee:
  defaultTags:
    - apigee

    Tag values are slugified and deduplicated. When API Hub supplies tags — the API categories and the API Style attribute (e.g. rest) — they are combined with the defaults: defaults first (in config order), then the API Hub tags.

    Sync behaviour

    • Runs on the configured schedule (default: every 60 minutes, with a 30-second initial delay and a 10-minute timeout).
    • A proxy that appears in several organisations is deduplicated into a single entity that records all of them.
    • Spec resolution runs with bounded concurrency and an LRU cache, keeping large catalogues fast and memory-bounded.
    • Every run emits a full catalog mutation, so proxies removed from Apigee disappear from the catalog on the next sync.
