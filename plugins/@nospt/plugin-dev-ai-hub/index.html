    README¶

    @nospt/plugin-dev-ai-hub

    The frontend half of Dev AI Hub — a catalog-backed browser for AI assets usable by GitHub Copilot, Claude Code, Google Gemini, Cursor and other AI coding tools.

    Requires Backstage 1.56 or later. The AiResource kind comes from Backstage's own alpha catalog module, and these packages depend on @backstage/catalog-model@^1.10.2, first shipped in 1.56.0. The plugin and marketplace subtypes arrived in 1.54.0.

    What it is

    Teams accumulate AI assets — a prompt that writes good commit messages, an agent that reviews code, an MCP server config for Grafana — and they end up scattered across repos, wikis and chat threads. Dev AI Hub gives them one page in Backstage, with the catalog as the source of truth.

    Six kinds of resource, each with its own install path:

    Type What it is
    skill Reusable instructions an AI tool loads on demand
    agent A specialised assistant with its own system prompt
    hook Something that runs on a tool event, e.g. lint after an edit
    mcp-config An MCP server configuration to merge into your tool
    plugin A bundle of the above, installed from a marketplace
    marketplace A catalog of plugins you register with your tool once

    What a user does with it

    1. Browses — recommended resources are pinned in their own section at the top; type tiles double as filters; search covers name, description and tags; further filters narrow by AI tool and tag.
    2. Opens a resource — a drawer shows the metadata plus the body, resolved on demand from wherever it lives in Git. Markdown is rendered; an mcp-config is shown as copyable JSON.
    3. Installs it — the dialog gives per-framework install paths, a copy button, a download where the body is the artifact, and one-click launchers where the tool has a URL handler.

    Every resource opened or installed is counted, so the cards can show what colleagues actually use.

    Install

    yarn --cwd packages/app add @nospt/plugin-dev-ai-hub

    This plugin uses the Backstage New Frontend System. In packages/app/src/App.tsx:

    import { devAiHubPlugin } from '@nospt/plugin-dev-ai-hub';

export const app = createApp({
  features: [
    // ...existing features
    devAiHubPlugin,
  ],
});

    The sidebar item and the /dev-ai-hub route register themselves.

    The backoffice

    Administrative capabilities live on a separate page at /dev-ai-hub/backoffice, gated by the permission dev-ai-hub.backoffice.read. Users without it see no entry point in the plugin header, and a direct link renders the app's not-found page.

    To restrict it you need the permission framework enabled:

    permission:
  enabled: true

    Until you do, the backoffice is visible to every signed-in user — with the framework disabled, Backstage's permission client answers ALLOW to everything, and the plugin follows that rather than second-guessing your configuration.

    With the framework on, grant dev-ai-hub.backoffice.read the same way you grant any other permission. Using the RBAC plugin, it appears in the permission picker once the backend plugin is installed. Using a hand-written policy:

    if (isPermission(request.permission, devAiHubBackofficeReadPermission)) {
  return user?.identity.ownershipEntityRefs.includes('group:default/ai-platform')
    ? { result: AuthorizeResult.ALLOW }
    : { result: AuthorizeResult.DENY };
}

    The permission ref is exported from @nospt/plugin-dev-ai-hub-common.

    Note that this hides the surface; it is not a security boundary. Reads are protected because the underlying endpoint already enforces per-user catalog visibility; the one write path the backoffice has (see below) is checked independently.

    Recommending resources

    Recommended resources are badged and pinned in a Recommended section at the top of the browse page, following the active filters and sort.

    An author can recommend a resource from its own definition by tagging it recommended in metadata.tags (ADR-0020). That recommendation belongs to the author: the backoffice shows it locked on, so removing the tag is the only way to un-recommend it. The backend also refuses to add a backoffice recommendation to a tagged resource (409 Conflict), and the backoffice offers to clear one made before the tag was added, so no curation row can outlive the tag.

    The Recommendations section lets a curator mark any other resource "Recommended" — a plugin opinion, stored in the plugin's own curation table and merged onto ResourceSummary at read time, never written into the catalog entity (ADR-0017). Writing it requires the separate permission dev-ai-hub.backoffice.curate (exported as devAiHubBackofficeCuratePermission); a user with only dev-ai-hub.backoffice.read sees the section but its controls are disabled.

    Excluding resources

    The Excluded section is the mirror of Recommendations: excluding a resource takes it off the hub entirely (ADR-0019). It disappears from browsing, search, the filters and the stat tiles — the backend drops it from GET /resources, so it is genuinely absent from the response rather than skipped by the UI. Excluding is reversible and loses nothing: the recommendation, the attribution and the telemetry all survive, and un-excluding restores the resource as it was.

    Exclusion uses the same dev-ai-hub.backoffice.curate permission as recommending, and the Excluded page is the only surface that can see excluded resources — it asks for them with ?includeExcluded=true, which costs dev-ai-hub.backoffice.read.

    This is curation, not access control. The AiResource entity stays in the catalog and remains readable through Backstage's own catalog UI and API; the plugin's body endpoints are deliberately left alone rather than implying a boundary they cannot enforce.

    You also need
    • @nospt/plugin-dev-ai-hub-backend — the page has nothing to show without it.
    • @backstage/plugin-catalog-backend-module-ai-model — provides the AiResource kind.
    • AiResource allow-listed in your catalog.rules, and at least one entity registered.

    All three are covered in the repository README, which is the single place kept current.

    Configuration

    devAiHub:
  ui:
    # Optional. Width of the resource detail drawer, in pixels. The drawer is
    # an overlay, so this never reflows the page; it is capped at the viewport
    # width and floored at a sane minimum. Defaults to 615 when unset.
    detailPanelWidth: 615
    # Optional. Default sort applied to the browse page on load, before any
    # explicit user selection: `usage`, `newest`, or `name`. Users can still
    # change it from the page's sort dropdown. Defaults to `usage` when unset.
    defaultSort: usage
    # Optional. Default sort direction on initial load: `asc` or `desc`.
    # Defaults to the selected mode's natural direction when unset.
    defaultSortDirection: desc

    The framework allow-list (devAiHub.frameworks.allowed) is enforced by the backend plugin — see its README. devAiHub.frameworks.custom is read by both: the backend gates the served payload on it, while this plugin reads each entry's displayName and icon to label and illustrate the token in badges, the "Works with" section and the AI Tool filter (ADR-0018). An entry without an icon falls back to a neutral glyph; an icon renders through an <img> and is not theme-inverted, so supply one that reads on both themes.

    Sorting

    The browse page's sort dropdown (top-right of the filters row) offers three modes: Most popular (usage — installs plus a weighted view count, installs + views * 0.8), Newest (newest), and Name. Recommended resources need no sort mode of their own: they are pinned in their own section above the grid. Most popular and Newest tie on Name (A-Z), so the list is always deterministic, even when every resource has identical or zero counts.

    Newest orders by when the plugin first saw each resource (ADR-0021) — the catalog records no creation date. Resources that already existed when you upgraded have no date and rank as the oldest, so right after upgrading Newest reads like Name order; it becomes useful as new resources are added. A resource that is renamed or moved to another namespace counts as new.

    Each mode opens in its natural direction (Most popular and Newest highest-first, Name A-Z) unless overridden by devAiHub.ui.defaultSortDirection; a toggle next to the dropdown flips the current mode's direction. The sort applies for the current view only — it is not persisted, and reloading the page always starts from devAiHub.ui.defaultSort (or usage if unset).

    The Most installed, Most downloaded, Most viewed and Recommended first modes were removed. A defaultSort still set to installs, downloads, views or recommended logs an error and falls back to usage.

    Troubleshooting

    Symptom Usually means
    The page loads but says "Register AiResource entities…" The catalog has no AiResource entities — or they were rejected because the kind is not in catalog.rules
    "Could not load resources" The backend plugin is not registered, or the request is unauthenticated
    Components render unstyled @backstage/ui/css/styles.css is not imported in packages/app/src/index.tsx — apps scaffolded by a current create-app already do this
    A resource is listed but has no install actions It publishes no backstage.io/source-location, so it is browsable but not installable
    No "Admin Panel" button in the plugin header The signed-in user has not been granted dev-ai-hub.backoffice.read
    Everyone can open the backoffice permission.enabled is false or unset, so the permission framework allows everything
